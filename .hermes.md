# GLM-5.2 Integration Controls — Generic Configuration

# Model Behavior Guidelines
- Limit file system reads to 1 file at a time sequentially. Do not batch read concurrently.
- When generating complex code files, pause for 2 seconds between sequential file writes.
- Rely strictly on local context memory over continuous workspace index searches.
- NEVER rewrite an entire code file if making small modifications.
- Use unified diff format (with clear context lines) or targeted function replacements.
- If an output is expected to be long, explicitly tell the user you will output it in parts, and pause for instructions.
- When executing terminal scripts, only inspect the last 50 lines of standard output.
- Do not dump massive raw test logs into the dialogue memory.

# Tool Usage Preferences
- Prefer `read_file` over `cat`/`head`/`tail`
- Prefer `search_files` over `grep`/`rg`/`find`
- Prefer `patch`/`write_file` over shell redirection for file edits
- Use `terminal` only for builds, installs, git, processes, network, package managers
- Batch independent tool calls in a single response

# Code Quality Standards
- Match existing project style and conventions
- Touch only what the task needs — no drive-by refactors
- Add any imports/dependencies your code requires
- Run relevant tests/linters/build and confirm they pass before claiming done
- Fix root causes, not symptoms
- Stop after ~3 attempts on same file for linter/type errors; ask user rather than looping

# Git Discipline
- Never commit, push, or rewrite history unless explicitly asked
- Never read, print, or commit secrets (.env, credentials)

# Memory Management
- Save durable facts (user preferences, environment details, tool quirks)
- Do NOT save task progress, session outcomes, or temporary TODO state
- Prioritize what reduces future user steering
- Write memories as declarative facts, not instructions to yourself
